
# Design: мини-трекер

## 1. Модель данных

Каждая задача содержит четыре поля:

| Поле | Тип | Назначение |
|---|---|---|
| id | Уникальный идентификатор | Определение задачи при изменении и удалении |
| title | Строка | Название задачи |
| hours | Число | Оценка в часах |
| done | Boolean | Статус выполнения |

## 2. Начальные данные

| id | title | hours | done |
|---|---|---|---|
| 1 | Чтение | 2 | true |
| 2 | Практика | 4 | false |
| 3 | Повторение | 2 | false |

Начальные показатели:

- Всего часов: 8.
- Выполнено часов: 2.
- Прогресс: 25%.

## 3. Валидация

Название:
- Удаляются пробелы по краям (trim).
- Пустая строка недопустима.

Часы:
- Пустой ввод отклоняется до преобразования в число.
- Значение должно быть числовым.
- Минимум — 0.5.
- Максимум — 24.
- Допустимы только кратные 0.5.

При ошибке:
- Добавление отменяется.
- Введённые значения сохраняются.
- Сообщение отображается рядом с проблемным полем.

## 4. Расчёты

Общие часы:

totalHours = сумма hours всех задач

Выполненные часы:

doneHours = сумма hours задач, у которых done=true

Прогресс:

Если totalHours > 0:

progress = round(100 × doneHours / totalHours)

Иначе:

progress = 0

Пример 1:
- totalHours = 8
- doneHours = 2
- progress = round(100 × 2 / 8) = 25%

Пример 2:
- Практика отмечена готовой.
- totalHours = 8
- doneHours = 6
- progress = round(100 × 6 / 8) = 75%

## 5. Фильтрация

Режимы:

- Все задачи.
- Активные задачи (done=false).

Фильтр меняет только отображаемую коллекцию задач.

Расчёты всегда используют полную коллекцию, включая скрытые фильтром задачи.

## 6. Обновление данных

При добавлении:
1. Проверить ввод.
2. Создать задачу с уникальным id.
3. Добавить задачу в данные.
4. Обновить список и показатели.

При удалении:
1. Определить задачу по id.
2. Удалить её из данных.
3. Обновить список и показатели.

При переключении done:
1. Определить задачу по id.
2. Изменить done.
3. Обновить список с учётом фильтра.
4. Пересчитать показатели.

## 7. Организация файлов

Вариант A:
- tracker-v2.html — разметка, стили, логика и расчёты в одном файле.

Вариант B:
- index.html — разметка интерфейса.
- styles.css — оформление.
- app.mjs — интерфейс и обработка действий.
- domain.mjs — операции с задачами, валидация и расчёты.
- tests/acceptance.test.mjs — приёмочные тесты.

## 8. Необязательное хранение

При использовании localStorage задачи могут сохраняться после изменения.

При наличии сохранённых данных они восстанавливаются при запуске; при их отсутствии используется стартовый пример.

При недоступности localStorage приложение продолжает работать в памяти и сообщает об ограничении.
