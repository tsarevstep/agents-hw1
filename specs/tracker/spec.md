
# Specification: Tracker

## Requirement 1: Управление задачами

Система MUST поддерживать добавление, удаление и переключение статуса выполнения задач.

Каждая операция MUST изменять фактические данные, а не только внешний вид интерфейса.

### Scenario: Добавление задачи

WHEN пользователь вводит корректное название и количество часов и добавляет задачу,
THEN задача появляется в данных и отображается в списке, если соответствует текущему фильтру.

### Scenario: Удаление задачи

WHEN пользователь удаляет задачу,
THEN задача исчезает из данных и списка, а показатели пересчитываются.

### Scenario: Переключение статуса

WHEN пользователь меняет done задачи,
THEN статус сохраняется в данных, а выполненные часы и прогресс пересчитываются.

## Requirement 2: Валидация

Система MUST проверять:

- Название после trim не должно быть пустым.
- Часы должны быть числом от 0.5 до 24 включительно.
- Шаг часов должен составлять строго 0.5.
- Пустое значение часов не должно интерпретироваться как 0.
- Некорректные значения не должны добавляться.

При ошибке система MUST отображать сообщение рядом с соответствующим полем и сохранять введённые значения для исправления.

### Scenario: Пустое название

WHEN пользователь вводит пустое название или только пробелы,
THEN задача не добавляется и рядом с названием появляется ошибка.

### Scenario: Некорректные часы

WHEN пользователь вводит пустые, отрицательные, нечисловые часы, значение меньше 0.5, больше 24 или не кратное 0.5,
THEN задача не добавляется и рядом с полем часов появляется ошибка.

### Scenario: Сохранение формы

WHEN валидация обнаруживает ошибку,
THEN введённые данные остаются в форме.

## Requirement 3: Расчёт показателей

Система MUST рассчитывать:

- Всего часов — сумму hours всех задач.
- Выполнено часов — сумму hours задач с done=true.
- Прогресс — округление до целого процента отношения выполненных часов к общим.

Если задач нет, система MUST показывать 0 часов и 0% прогресса.

Результат MUST NOT содержать NaN или Infinity.

### Scenario: Начальное состояние

GIVEN стартовые задачи:
- Чтение — 2 ч, done=true.
- Практика — 4 ч, done=false.
- Повторение — 2 ч, done=false.

WHEN приложение отображает стартовый пример,
THEN всего 8 ч, выполнено 2 ч, прогресс 25%.

### Scenario: Выполнение практики

WHEN задача «Практика» отмечена готовой,
THEN выполнено 6 из 8 часов и прогресс равен 75%.

### Scenario: Удалены все задачи

WHEN все задачи удалены,
THEN всего 0 ч, выполнено 0 ч, прогресс 0%.

## Requirement 4: Фильтрация

Система MUST поддерживать отображение всех и активных задач.

Фильтр MUST влиять только на видимый список.

Общие часы, выполненные часы и прогресс MUST рассчитываться по всем задачам независимо от фильтра.

### Scenario: Фильтр активных

GIVEN исходный набор задач и прогресс 25%,

WHEN пользователь включает фильтр «активные»,
THEN отображаются только задачи с done=false, а прогресс остаётся 25%.

## Requirement 5: Интерфейс

Система MUST:

- Оставаться читаемой на ширине 390 px.
- Не создавать горизонтальную прокрутку на этой ширине.
- Иметь подписанные поля ввода и кнопки.
- Показывать ошибки рядом с соответствующими полями.

### Scenario: Узкий экран

WHEN интерфейс отображается при ширине 390 px,
THEN содержимое читаемо, элементы управления подписаны и горизонтальная прокрутка отсутствует.

## Requirement 6: Автономность

Система MUST работать без CDN, внешних библиотек и API-ключей.

Вариант A MUST быть реализован в одном файле `tracker-v2.html`.

Вариант B MUST использовать указанные в proposal.md пять файлов.

## Optional: localStorage

Система MAY сохранять задачи в localStorage.

Если сохранение реализовано и хранилище недоступно, система MUST продолжать работу в памяти и показывать понятное сообщение.
